# 문제 정의 인사이트와 예시

다시 정의한 문장의 형식:
> ○○(사람)가 ○○(상황)에서 ○○(표면 문제)가 아니라 ○○(진짜 문제) 때문에 ○○(손실)를 겪는다.

## 1. 표면 요청은 "속도·편의", 진짜 문제는 "손실"이다
| 패턴 | 처음 요청 | 다시 정의한 문제 |
|---|---|---|
| 패턴1 | 매일 보고서 만드는 시간을 줄여 달라 | 반복 경고 속에 가장 심각한 경고가 묻혀 놓친다 (실제 손실 사건 있음) |
| 패턴2 | AI로 답장을 빨리 쓰게 해 달라 | 급한 문의가 일반 문의에 묻혀 며칠 방치된다 (고객 분쟁으로 번짐) |
| 패턴3 | 신입이 혼자 연습하게 해 달라 | 신입이 근거 없이 원인을 말한다 (평가 항목 중 '근거'가 최저) |
→ "안 고치면 어떤 일이 생겨요? 최근에 문제가 된 적 있어요?"

## 2. 맞히려 하지 말고, 사람이 결정하도록 도와라
- 패턴4: "무엇이 뜰지 먼저 감지하라" → "마감 전 회의에서 이번 주 작은 시험 기회를 어느 후보에 줄지 정한다"
- 예측은 맞는지 검증할 수 없지만, 결정 기준은 테스트할 수 있다.
→ "그 결과를 누가, 언제, 어떤 결정에 써요?"

## 3. AI를 못 믿는 이유는 성능이 아니라 신뢰다. 신뢰는 이미 검증된 사람에게서 빌려 와라
- 패턴5: "AI 추천이 실제 구매까지 이어지게" → "추천은 의심받지만 직접 경험한 사람의 기록은 믿는다" → 실제 경험 콘텐츠를 지금 살 수 있는 상품으로 연결
- 패턴3: "AI가 신입을 코칭" → "선임이 이미 쓰는 질문 방식을 그대로 연습에 옮긴다"
→ "지금 이 판단을 할 때 누구 말이나 어떤 자료를 믿으세요?"

## 4. 같은 문제도 범주를 바꾸면 풀린다
| 패턴 | 처음 정의 | 다시 정의 | 결과 |
|---|---|---|---|
| 패턴6 | 대기 장치가 느리다 (속도) | 기다림이 지루하다 (체감) | 기다리는 동안 볼거리 제공, 불만 감소 |
| 패턴7 | 가입 절차가 복잡하다 (사용성) | 사용자가 그 단계를 두려워한다 (감정) | 안심시키는 안내 추가, 가입률 크게 증가 |
| 패턴8 | 구성원 역량 부족 (기술) | 몰입이 낮다 (동기) | 자율성 확대, 만족도 상승 |
→ "이게 혹시 ○○ 문제가 아니라 ○○ 문제는 아닐까요?" (속도·신뢰·감정·습관·동기)

## 5. 기능 요청 뒤에는 다른 필요가 있다
- 패턴9: 분석 대시보드 요청 → 내보내기 → 문서 출력 요청 … 실제로는 매주 남에게 보여 줄 차트 한 장
- 패턴2: "AI 자동 답장" → 신입이 내용을 알고 보내는 것(모국어 대역) + 돈이 걸린 약속은 승인 후
→ "그게 생기면 무엇을 하시려고요?"

## 6. "회사"가 아니라 "그 결정을 내리는 한 사람"으로 좁혀라
- 패턴4: 회사가 흐름을 잡는다 → 마감 전 주간 회의에서 후보를 고르는 담당자
- 패턴1: 운영팀 → 매일 아침 회의 전에 보고서를 보는 담당자
- 패턴2: 고객 응대팀 → 내일 처음 출근하는, 외국어를 잘 모르는 신입
→ "이걸 누가, 언제, 어떤 상황에서 써요?"

## 7. 잘 된 예외에 원인이 있다
"왜 안 될까?" 대신 "잘 됐던 때는 뭐가 달랐나?"를 묻는다. 차이가 원인을 가리킨다.
- 패턴10: 장기 과제가 늘 흐지부지 → 진행된 회의에는 의욕 있는 주니어가 있었다 → 의지가 아니라 "회의 뒤 맡아 끌고 갈 사람이 없다"
- 패턴1: 심각한 경고를 잡았던 날은 반복 경고가 적었다 → 부주의가 아니라 반복 경고에 묻힘
- 패턴2: 빨리 처리된 급한 문의는 제목에 핵심 단어가 있었고, 놓친 건 다른 채널·다른 언어로 온 것 → 채널·언어 때문에 눈에 안 띔
→ "이게 잘 처리됐던 날도 있었어요? 그날은 뭐가 달랐어요?" (탓하는 질문 대신)

## 8. 근본 문제를 찾아도 만들 것은 판단 하나로 좁혀라
- 패턴11: 부서마다 데이터와 기준이 달라 한 맥락으로 못 본다는 근본 문제를 찾았지만, 플랫폼 전체를 만들려다 범위가 넓어짐
- 패턴4: "시험 기회 배정" 판단 하나만 끝까지 증명
→ "이번엔 이것 하나만 확실히 하고, 나머지는 빼도 될까요?"
